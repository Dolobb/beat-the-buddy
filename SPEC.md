# Beat the Buddy — ТЗ (Telegram HTML-виджет, Bot API 10.4)

Игра в духе Kick the Buddy / Beat the Boss: игрок выбирает одного из 6 друзей и лупит его
рэгдолл разным оружием, получает монеты, открывает оружие. Общий лидерборд на всех игроков.

## Правила для исполнителя
- Bot API 10.4 вышел 9.11.2026, в твоих знаниях его нет. Источник правды: `docs/tg/widgets.md`
  (гайд, обязательно прочитай разделы Gestures, Requests to the bot, What widgets support,
  Limits, TelegramWidget, блок «Writing widgets with an LLM») и `docs/tg/api.md` (методы и типы).
  НЕ выдумывай методы и поля. Всё, что вне «widget profile», клиент молча вырезает.
- НЕ создавай и НЕ переключай git-ветки, не коммить. Сеть недоступна: `npm install` не запускай,
  `terser` уже стоит в node_modules. Никаких новых зависимостей.
- Node 25: TypeScript запускается нативно (`node file.ts`), поэтому только erasable-синтаксис:
  без enum, namespace, parameter properties. Импорты с расширением `.ts`.
- Пиши компактно, без абстракций «на вырост». Никаких классов-обёрток, DI, интерфейсов с одной реализацией.
- Отчёт в конце: что сделано, итоговый размер (raw и zlib), что вырезано из-за размера, что не проверено.

## config.ts
```ts
export const friends = [ // ровно 6; id = имя файла лица faces/<id>.webp|png|jpg (необязателен)
  { id: 'max', name: 'Макс', color: '#e74c3c' }, ...ещё 5 заглушек с разными цветами
];
export const weapons = [ // порядок = индекс; поведение зашито в виджете по индексу
  { name: 'Кулак',   icon: '👊', price: 0,    dmg: 1 },
  { name: 'Тапок',   icon: '🩴', price: 50,   dmg: 2 },
  { name: 'Бита',    icon: '🏏', price: 300,  dmg: 5 },
  { name: 'Пулемёт', icon: '🔫', price: 1500, dmg: 1 },
];
export const phrases = ['Ай!', 'За что?!', 'Хватит!', 'Мама!'];
export const HP = 100, KO_BONUS = 20;
```
Монеты за удар = dmg оружия. Нокаут (HP<=0) даёт KO_BONUS.

## Протокол
Все лимиты: request data 1–64 байта, ответ ≤1024 байта, chat_data/public_data ≤1024 байта.

**Запросы виджет → бот** (`TelegramWidget.request(data)`), числа десятичные:
- `h:<f>:<hits>:<coins>` — накопленная дельта: по другу с индексом f нанесено hits ударов, заработано coins.
  Шлётся фоном не чаще раза в 5 с, только если есть неотправленное, плюс один раз при старте (`h:0:0:0`,
  чтобы получить авторитетное состояние).
- `b:<w>:<f>:<hits>:<coins>` — купить оружие w, заодно применить дельту. Только из обработчика тапа.
- `f:<f>` — получить лицо друга f.

**Ответы бота** (`answerWidgetQuery.data`), на КАЖДЫЙ запрос, даже ошибочный:
- на `h` и `b`: `{"c":<монеты>,"w":<битмаска открытого оружия>}` — авторитетное состояние игрока.
  Виджет заменяет им своё (минус ещё не отправленная дельта учитывается прибавкой локально).
- на `f`: строка `data:image/...;base64,...` целиком ≤1024 байт, либо ответ без data, если файла нет или он не влезает.

**Валидация в боте** (state.ts): f в 0..5, w в 0..3, hits 0..300 за запрос, coins ≤ hits*5 + KO_BONUS*ceil(hits/20)
(грубый потолок от накрутки; иначе дельта отбрасывается, ответ всё равно с текущим состоянием).
Покупка: оружие не открыто и монет хватает после применения дельты. Бит 0 (кулак) открыт всегда.

**chat_data** (на сообщение): `{"c":..,"w":..}` — задаётся только при отправке виджета из базы бота.
Виджет при старте: состояние = localStorage, если есть, иначе chatData, иначе {c:0,w:1}.

**public_data** (общий на всех, shared widget): `{"r":<ревизия>,"v":[6 чисел: сколько ударов получил каждый друг],
"t":[["Имя",удары],...]}` — t это топ-3 игроков по нанесённым ударам (first_name, обрезать до 12 символов).
Виджет зовёт `watchPublicData()`, игнорирует ревизии старше уже виденной.

## bot.ts
- Токен из `process.env.BOT_TOKEN`, без него понятная ошибка. Long polling `getUpdates` с timeout 30,
  `allowed_updates: ["message","widget_query","shared_widget_query"]`. Ошибки сети: лог, пауза 3 с, продолжить.
- При старте читает `dist/widget.html`; нет файла — ошибка «сначала npm run build».
- `/start`: если в базе нет shared-виджета или его `htmlHash` (sha1 от dist/widget.html) другой —
  `sendWidget` c `html`, `is_shared:true`, `allow_queries:true`, `height:` (константа из виджета, см. ниже),
  `public_data`, `chat_data` игрока; сохранить `message.widget.id` и hash; сразу `editSharedWidgetData`
  с `cache_time:5`. Иначе `sendSharedWidget` с `widget_id` и `chat_data`. Подпись (caption) не нужна.
- `widget_query` и `shared_widget_query` обрабатываются одинаково по `from.id` → state.ts → `answerWidgetQuery`.
- После изменения счётчиков: `editSharedWidgetData` с debounce 2 с (лимит 1 правка в секунду), ревизия r++.
- База: `data.json` в корне: `{ widget:{id,htmlHash}, rev, victims:[6], users:{ [id]:{name,c,w,hits} } }`.
  Запись атомарная (tmp + rename), debounce 1 с, плюс сброс на SIGINT/SIGTERM.
- Лица: `faces/<id>.(webp|png|jpg)`, читаются при запросе `f`.
- Ошибки API логировать с `description` из ответа Telegram.

## state.ts
Чистые функции над объектом базы, например `applyQuery(db, userId, name, data): string | undefined`
(возвращает строку ответа для h/b; для `f` бот обрабатывает сам) и `publicData(db): string`.
Тест `state.test.ts`: дельта начисляется; накрутка отбрасывается; покупка без денег не проходит;
покупка с деньгами списывает и ставит бит; мусор в data не роняет и не меняет базу; publicData ≤1024 байт
при длинных именах.

## Виджет
ЖЁСТКИЙ ЛИМИТ: `dist/widget.html` ≤ 4096 байт после zlib level 9 (считать ТОЛЬКО так:
`python3 -c 'import sys,zlib; print(len(zlib.compress(sys.stdin.buffer.read(), 9)))' < dist/widget.html`)
и ≤ 32768 байт сырого. Цель ≤ 4000. Это главный риск задачи: пиши исходник сразу экономно
(короткие повторяющиеся конструкции сжимаются хорошо, уникальный текст и emoji — плохо).

Раскладка, фиксированная высота 440 px, ширина = ширина бабла (320–430 на телефоне, проектировать под 320):
1. Шапка: монеты 🪙, имя текущего друга, кнопка «сменить», полоска HP.
2. Canvas-сцена ~300 px высотой, `touch-action:none`, масштаб по devicePixelRatio.
   Ширину читать один раз при старте и на событие `activated`, НЕ каждый кадр.
3. Ряд из 4 кнопок оружия: открытое — иконка, выбранное подсвечено, закрытое — иконка и цена;
   тап по закрытому = покупка (запрос `b`), если монет не хватает — ничего не слать, мигнуть ценой.
4. Строка лидерборда из publicData: «Огрёб: <имя друга> N · Топ: <имя> N».
   Учесть время в углу сообщения: нижняя строка с `padding-bottom: env(safe-area-inset-bottom)`, `body{margin:0;padding:0}`.
Экран выбора друга: 6 кнопок (имя на фоне color) поверх/вместо сцены; показывается при первом запуске и по «сменить».
Цвета интерфейса — через `--tg-theme-*`, чтобы работали обе темы.

Сцена:
- Рэгдолл на Verlet: ~11 точек (голова, шея, таз, локти, кисти, колени, стопы), палки-связи, гравитация,
  отскок от стен и пола, 2–3 итерации связей. Тело цвета `color` друга, голова — круг.
  Лицо: если есть картинка (см. ниже) — `drawImage` в круг головы (clip), иначе первая буква имени и глаза-точки.
  По мере урона голова краснеет (наложить полупрозрачный красный через rgba fill), при KO — глаза-крестики.
- Оружие (действие в точке тапа):
  0 Кулак: импульс точкам в радиусе ~50 px от тапа.
  1 Тапок: снаряд летит от края к точке тапа, при попадании в радиус точки тела — импульс.
  2 Бита: сильный импульс в большом радиусе + тряска сцены на несколько кадров.
  3 Пулемёт: пока палец/кнопка удерживается — выстрел в позицию указателя ~8 раз/с
     (pointerdown/pointermove/pointerup/pointercancel; на cancel обязательно прекратить).
  Промах мимо тела монет не даёт.
- Попадание: HP -= dmg, монеты += dmg, всплывающее «+N» и пара частиц-звёздочек (рисовать на canvas,
  НЕ DOM-элементами), `HapticFeedback.impactOccurred('light')` (для биты 'heavy'), изредка фраза из phrases
  в пузыре на canvas. HP<=0: нокаут, +KO_BONUS, тело обмякает ~2 с, затем HP=100 и респаун в центре.
- Цикл: requestAnimationFrame; на `deactivated` остановить, на `activated` продолжить. Никаких layout-чтений
  в кадре. Не превышать 4000 команд canvas за кадр (их будет на порядок меньше).
- Когда тело в покое и ввода нет, можно не перерисовывать (экономия CPU-квоты 300 мс/с).

Состояние и сеть:
- localStorage ключ `s`: `{c,w,f,k}` (монеты, маска, выбранный друг, выбранное оружие) — писать при изменении,
  не чаще раза в секунду, в try/catch. Неотправленная дельта (hits, coins по текущему другу) — там же или
  отдельным ключом, чтобы не терялась при пересоздании виджета; при смене друга дельту сначала отправить
  или хранить по другу.
- Один запрос одновременно. Тикер раз в 5 с: если есть ожидающий запрос лица — он, иначе дельта, если не пусто.
  Ошибки (`BUSY`, `RATE_LIMITED`, `TIMEOUT`, `FAILED`, `NOT_ALLOWED`) молча: дельта остаётся и уйдёт позже.
  Дельту вычитать из неотправленного только после успешного ответа.
- Лицо: при выборе друга, если в localStorage нет `f<i>` — запрос `f:<i>` (сразу из тапа, при отказе — через тикер).
  Ответ класть в localStorage `f<i>`; на QuotaExceededError удалить все ключи `f*` и повторить один раз.
  Картинка: `new Image()` с data: src, рисовать после `load`.
- Виджет должен работать и без `window.TelegramWidget` (в preview есть заглушка, но проверяй `TW &&`).

Если не влезает в 4096, резать в таком порядке (и сказать в отчёте): фразы → частицы → тряска →
всплывающие «+N» → покраснение головы. Механики оружия, монеты, покупку, сохранение, синхронизацию,
лидерборд и лицо-картинку резать нельзя.

## scripts/build.ts
- Берёт `widget/widget.html`, подставляет вместо маркера `__CFG__` компактный JSON
  `{f:[[name,color],...], w:[[icon,price,dmg],...], p:phrases, hp:HP, ko:KO_BONUS}` (имена оружия в виджет не кладём).
- Минифицирует `<script>` через terser (`toplevel:true`, `compress:{passes:3, unsafe:true}`, mangle), CSS и HTML —
  простым удалением лишних пробелов/переводов строк. Пишет `dist/widget.html`.
- `dist/preview.html` = заглушка `TelegramWidget` и CSS-переменные темы из раздела «A first look in a browser»
  гайда + тот же виджет в контейнере шириной 360 px. Заглушка `request` должна отвечать как бот
  (в памяти: начислять дельту, продавать оружие, на `f` отвечать null), publicData — правдоподобный пример.

## scripts/size.ts
Считает raw-байты и zlib-9 через `python3` (команда выше, через child_process с stdin), печатает оба числа
и лимиты, `process.exit(1)` если raw > 32768 или zlib > 4096 или в файле есть NUL.
