# Beat the Buddy — мини-апп (Telegram Mini App)

Полноценная версия игры в духе Kick the Buddy / Beat the Boss: рэгдолл друга на настоящей физике, его можно
хватать, швырять об стены, бить и расстреливать. Монеты, магазин оружия, общий рейтинг. Виджет (SPEC.md)
остаётся как есть и НЕ трогается: файлы bot.ts, state.ts, widget/, scripts/build.ts, scripts/size.ts менять нельзя.

## Правила для исполнителя
- НЕ создавай и НЕ переключай git-ветки, не коммить. Сети нет, `npm install` не запускать, новых зависимостей нет.
- Node 24/25, TypeScript нативно: только erasable-синтаксис, импорты с `.ts`. Сервер — без зависимостей (node:http, node:crypto, node:fs).
- Клиент — обычные ES-модули без сборщика и без фреймворков. Уже лежат и готовы к использованию:
  `app/vendor/matter.min.js` (Matter.js 0.20, глобал `Matter`), `app/vendor/telegram-web-app.js` (официальный SDK,
  глобал `Telegram.WebApp`; подключать ЛОКАЛЬНО, не с telegram.org — у игроков этот домен заблокирован),
  `app/assets/*.png` и `app/assets/manifest.json` (генерирует scripts/assets.py, не править).
- ВСЕ URL в клиенте относительные (`./api/sync`, `./assets/...`): приложение будет жить по адресу
  `https://<домен>/buddy/`, а не в корне.
- Пиши компактно, без абстракций на вырост. Но это игра: сочность (juice) важнее минимализма — частицы, тряска,
  звук, отдача обязаны быть.
- Отчёт в конце: что сделано, что не сделано/упрощено, что не проверено.

## Ассеты (уже готовы)
`app/assets/manifest.json`: `{heads:{f1:[w,h],...}, bodies:{naked:{torso:[w,h],arm,hand,thigh,shin}, f1:{...}, f3:{...}}}`.
- Головы: `head-<friendId>.png` (ширина 320, прозрачный фон, внизу шея). Если в манифесте есть `<id>-hurt` / `<id>-ko` —
  использовать их при HP < 50% / в нокауте; сейчас их нет, поэтому фолбэк обязателен: синяки и пластыри рисуются
  поверх кодом (полупрозрачные фиолетовые пятна, растущие с уроном), в нокауте — крестики на глазах и звёздочки по кругу.
- Тела: `body-<sheet>-<part>.png`, part ∈ torso, arm (плечо), hand (предплечье с кистью), thigh (бедро), shin (голень со стопой,
  носок смотрит ВПРАВО). Каждая деталь вертикальна, сустав СВЕРХУ. Левая рука/нога — зеркало правой (ctx.scale(-1,1)).
  На торсе сверху торчит шея — голова рисуется поверх и перекрывает её.
- Листы: `naked` (трусы, есть у всех, по умолчанию), `f1` (одежда Пешки), `f3` (худи Боба).
  config: у друга необязательное `outfit: 'f1'`. Кнопка 👕 переключает naked ↔ свой костюм, только если он есть.

## Сервер (server.ts + appstate.ts)
- `PORT` (по умолчанию 8787), слушать 127.0.0.1. `BOT_TOKEN` из env обязателен, кроме `DEV=1`.
- Статика из `app/` (с правильными Content-Type, защита от `..`, `Cache-Control: no-cache` для html/js/json, `max-age=86400` для png).
  Запросы приходят как с префиксом `/buddy/`, так и без него — срежь необязательный префикс `/buddy`.
- База `appdata.json` в корне (формат как у бота: `{rev, victims:[6], users:{[id]:{name,c,w,hits,seq}}}`), атомарная запись
  (tmp+rename), debounce 1 с, сброс на SIGINT/SIGTERM. Если `appdata.json` нет, а `data.json` есть — стартовать с копии
  (перенос прогресса из виджета; маску оружия `w` при переносе сбросить в 3: Рука и Кулак, т.к. список оружия другой).
- **Авторизация**: тело каждого POST содержит `initData` (строка `Telegram.WebApp.initData`). Проверка по официальному
  алгоритму: secret = HMAC_SHA256(key="WebAppData", msg=bot_token); hash = hex(HMAC_SHA256(key=secret, msg=data_check_string)),
  data_check_string = пары `key=value` кроме `hash`, отсортированные по key, через `\n`. Сравнение timingSafeEqual.
  `auth_date` не старше 24 ч. Пользователь — JSON из поля `user` (id, first_name). Невалидно → 401.
  `DEV=1`: при пустом initData пользователь `{id:1, first_name:'Dev'}`.
- **API** (JSON):
  - `GET  api/config` → `{friends:[{id,name,color,outfit?}], weapons:appWeapons, hp, ko, phrases:{общие и по друзьям}}`
  - `POST api/sync` `{initData, seq, f, hits, coins, buy?}` → `{c, w, seq}`. `seq` — монотонный номер пакета клиента;
    если `seq <= user.seq` — пакет уже применён, вернуть состояние без изменений (идемпотентность при ретраях).
    Валидация: f 0..5, hits 0..2000, coins ≤ hits*maxDmg + APP_KO_BONUS*ceil(hits*maxDmg/APP_HP) + запас на урон от столкновений
    (сделай потолок разумным и опиши в коде одной строкой). `buy` — индекс оружия: купить после применения дельты, если хватает.
    Первый запрос клиента — `hits:0, coins:0, seq:0` для получения состояния (seq:0 всегда «уже применён»).
  - `GET  api/top` → `{victims:[{name,hits}] по убыванию, fighters:[{id,name,hits}] топ-20}`
- Лимит тела запроса 4 КБ. Любая ошибка → JSON `{error}` с кодом, сервер не падает.
- Тесты appstate.test.ts: подпись initData (сгенерируй валидную тем же алгоритмом в тесте; подделка и протухшая — отказ),
  дельта, идемпотентность по seq, накрутка, покупка, перенос из data.json, top.

## Клиент
Портретная ориентация, на весь экран WebView. `Telegram.WebApp.ready(); expand(); disableVerticalSwipes()` (если есть);
цвета шапки под тему. Вне Telegram (`initData` пуст) игра должна работать с сервером в DEV-режиме.

**Раскладка**: canvas на весь экран (devicePixelRatio, ресайз), поверх DOM-элементы:
- Верх: 🪙 монеты (анимированный счётчик), имя друга, полоса HP, кнопки: 👥 выбор друга, 👕 костюм, 🏆 рейтинг, 🔊/🔇.
- Низ: горизонтально прокручиваемая лента оружия (иконка, название, цена или «куплено»; выбранное подсвечено; на которое
  не хватает — приглушено). Тап по закрытому при достатке монет — покупка с подтверждением вторым тапом.
- Экраны-оверлеи: выбор друга (сетка 2×3 с головами и именами, счётчик «огрёб N»), рейтинг (два списка, я подсвечен).
- Фон сцены: простая комната кодом (стена, пол, плинтус, пара деталей), без картинок.

**Физика (Matter)**: стены, пол, потолок по краям сцены (между верхней и нижней панелью). Рэгдолл: голова (круг), торс,
2 плеча, 2 предплечья, 2 бедра, 2 голени; суставы — Constraint с небольшой податливостью; части одного тела не сталкиваются
между собой (collisionFilter.group < 0). Масштаб персонажа — около 55% высоты сцены. Чтобы он не валялся кучей:
«кукловод» — мягкая пружина от головы к точке над центром сцены + стабилизация угла торса; пока жив, он стоит/висит и
возвращается в стойку; в нокауте пружина отключается (обмякает), через 2.5 с — респаун.
Отрисовка — свой рендер на canvas (НЕ Matter.Render): спрайты по позиции и углу тел, сустав спрайта = верх детали.
Порядок: дальняя рука, дальняя нога, торс, ближняя нога, голова, ближняя рука. Голова крупная (мультяшная пропорция),
ширина ≈ 1.3 ширины торса.

**Урон и монеты**: монеты = нанесённый урон (округлять). HP ≤ 0 → нокаут, +ko монет, звёздочки, фраза.
- hand: тап — слабый тычок (1 урон); drag — захват ближайшей части (Constraint к пальцу), отпускание — бросок.
  Удар тела о стену/пол на скорости выше порога даёт урон пропорционально скорости (ограничь сверху ~15 за удар,
  с коротким кулдауном на часть тела, иначе монеты текут от дрожания).
- melee: импульс частям в radius от точки, урон один раз за взмах; анимация взмаха иконки оружия.
- throw: физическое тело-снаряд (рисуется иконкой) летит от ближнего края в точку тапа, урон при контакте с рэгдоллом, исчезает через 3 с.
- gun: пока палец на экране — выстрелы каждые rate мс от края экрана к пальцу: трассер, вспышка, гильзы-частицы; попадание,
  если луч проходит через часть тела; импульс в точке попадания.
- bomb: снаряд, после fuse (или при контакте, если fuse 0) — взрыв: радиальный импульс, урон по убыванию с расстоянием,
  вспышка, дым, сильная тряска. Ядерка: белая вспышка на весь экран.
- drop: предмет падает сверху над точкой тапа с большой массой, урон при контакте.

**Сочность**: всплывающие «+N» (крупнее при большом уроне), искры/звёзды при ударе, тряска камеры по силе, покраснение/синяки,
пузырь с фразой (свои у друга, иначе общие; чаще при сильных ударах), hit-stop 40–60 мс на тяжёлых ударах,
`HapticFeedback.impactOccurred` light/medium/heavy по урону, `notificationOccurred('success')` при покупке.
Комбо-счётчик: удары подряд с паузой < 1.5 с дают множитель монет ×1…×3 (покажи на экране; сервер это покрывает запасом потолка).

**Звук (sfx.js)**: WebAudio-синтез без файлов: punch (низкий удар + шум), slap, shot, laser, boom (длинный низкий шум),
coin, buy, ko, ui-click. AudioContext создаётся/возобновляется по первому pointerdown. Кнопка mute, состояние в localStorage.
Ограничь число одновременных голосов (пулемёт не должен хрипеть).

**Сеть (net.js)**: дельта копится по другу. Отправка `api/sync` раз в 5 с при непустой дельте, сразу при покупке и при
`visibilitychange → hidden` (fetch с keepalive). Один запрос одновременно. `seq` растёт только когда формируется новый пакет;
неподтверждённый пакет ретраится с тем же seq и тем же содержимым. Неотправленное и seq хранить в localStorage.
Монеты на экране = серверные + неподтверждённые. Офлайн — игра продолжается, плашка «нет связи».
localStorage: выбранный друг, оружие, костюм, mute.

**Производительность**: 60 fps на среднем телефоне. Пул частиц с лимитом (~200), без аллокаций в кадре где возможно,
картинки грузятся заранее с экраном загрузки. Когда вкладка скрыта — цикл остановить.

## Деплой (deploy/)
- `nginx-location.conf`: блок для вставки в существующий server{} сайта: `location /buddy/ { proxy_pass http://127.0.0.1:8787; ... }`
  с заголовками и `client_max_body_size 8k`.
- `buddy.service`: systemd-юнит, WorkingDirectory=/opt/buddy, `node --env-file=.env server.ts`, Restart=always, отдельный пользователь не нужен (www-data).
- `README-deploy.md`: шаги выкладки rsync-ом, и настройка в @BotFather: /newapp → URL `https://<домен>/buddy/`,
  ссылка вида `t.me/<bot>/<shortname>`, кнопка меню.

## Приёмка (выполни сам)
1. `npm test` — зелёный (старые тесты виджета тоже).
2. `DEV=1 PORT=8791 node server.ts &` → `curl` на `/buddy/`, `/buddy/api/config`, `/buddy/api/top`, POST `/buddy/api/sync` дважды
   с одним seq (второй раз состояние не меняется), затем убей процесс. Приведи вывод.
3. `npm run build && npm run size` по-прежнему проходит (виджет не сломан).
4. `node --check app/*.js` без ошибок.
5. Перечитай клиент: нет абсолютных URL, нет обращений к внешним доменам, все пути ассетов из манифеста.
