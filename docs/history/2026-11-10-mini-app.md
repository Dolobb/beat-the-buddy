# Beat the Buddy mini-app Implementation Plan

**Goal:** реализовать SPEC-APP.md полностью, сохранив виджет.
**Architecture:** независимые чистое состояние и HTTP API; ES-модули клиента с Matter и собственным canvas-рендером.
**Tech Stack:** Node 24/25, erasable TypeScript, browser ES modules, локальные Matter и Telegram SDK.
**Spec:** /SPEC-APP.md

## Global Constraints
- Не создавать/переключать ветки, не коммитить, не устанавливать зависимости и не использовать сеть.
- Не менять bot.ts, state.ts, widget/, scripts/build.ts, scripts/size.ts и готовые ассеты.
- Только относительные URL клиента; API работает с /buddy/ и без префикса.

## Review Focus
- Потерянный ответ синхронизации, перезагрузка и офлайн не удваивают и не теряют награду.
- Перенос данных не меняет исходную базу виджета.
- Ошибки авторизации/JSON/пути/размера запроса оставляют сервер работающим.
- Смена друга, костюма, ресайз и скрытие вкладки корректно сбрасывают ввод.
- Все виды оружия имеют различимое поведение, кукла восстанавливает стойку.

## Решения и исправления
- SPEC-APP.md задаёт архитектуру; новые ветки/коммиты/worktree и сетевые операции исключены по прямому запрету спецификации.
- API и физика реализованы в независимых областях, затем проверены совместно; отдельный read-only review нашёл unsupported fullscreen в DEV.
- Fullscreen ограничен Telegram >=8.0. Отмена ввода не засчитывает тычок. Отсутствующий таймер KO представлен null, чтобы нокаут в момент 0 корректно респаунился.
- Серверная симуляция и multi-device протокол не добавлялись: потолок награды и общий seq соответствуют ТЗ; ограничения описаны в deploy README.
